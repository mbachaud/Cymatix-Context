# W2.4 — delivered-seat floor (budget-cut fix) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Documents the ranking already placed in the delivered window should
not lose their seat to the token budget — a default-inert `[budget]
min_delivered_docs` floor switches the trimmer from seat-eviction to
content-truncation once the floor is reached.

**Architecture:** The Stage-5 trimmer (`context_manager.py:3577-3592`) evicts
whole lowest-scored documents until the assembled prompt fits — at shipped
defaults the compressor is off (`[ribosome] backend="none"`), so parts enter
at full length and eviction is the ONLY budget tool; that is the cat-(b)
mechanism (gold at map rank 9–12, `delivered_count` 2–8; 5 semantic needles
+ analogs elsewhere, receipts `ladder_v09x_w1c_*`). The fix: evict only down
to `floor = min(min_delivered_docs, n_parts_initial)`; below that, shrink
the LARGEST remaining parts (tail-truncate, header-preserving, marked) until
the prompt fits; if every part is at the minimum char floor and the prompt
STILL exceeds budget, resume eviction — the token budget is the hard
contract with the consumer and always wins last.

**Tech Stack:** stdlib only; no new deps.

**Spec:** `docs/research/2026-08-28-wave2-semantic-ranking-graph-research.md`
§5 "adjacent free win" + §7 W2.4; crater receipt cat-(b) ids erb_176, 181,
187, 237, 272 (combo arm).

### Task 2: trimmer floor + truncation fallback

**Files:** Modify `cymatix_context/context_manager.py:3577-3592`,
Test `tests/test_min_delivered_floor.py` (fixture cloned from
`tests/test_score_aware_budget_trim.py::manager_five_genes`).

Loop restructure (behavior, exact code at implementation):

```python
_floor = min(self.config.budget.min_delivered_docs, len(parts))
_TRUNC_MIN_CHARS = 280
_TRUNC_MARK = " ...[budget-trimmed]"
_budget_truncated = 0
while est_tokens > budget and len(parts) > 1:
    if _floor >= 2 and len(parts) <= _floor:
        # Seat floor reached: shrink the largest part instead of
        # evicting. 75% per pass; stop shrinking a part at
        # _TRUNC_MIN_CHARS. If NO part can shrink further, fall through
        # to eviction below the floor — budget always wins last.
        idx = max(range(len(parts)), key=lambda i: len(parts[i]))
        if len(parts[idx]) > _TRUNC_MIN_CHARS:
            new_len = max(_TRUNC_MIN_CHARS, int(len(parts[idx]) * 0.75))
            parts[idx] = parts[idx][: new_len - len(_TRUNC_MARK)].rstrip() + _TRUNC_MARK
            _budget_truncated += 1
            <recompute expressed/est_tokens>
            continue
        _floor = 0  # every part at min chars and still over: evict
        continue
    <existing eviction body unchanged>
```

Metadata: `budget_truncated` count added next to `budget_evicted`;
cap_binding stays driven by `budget_evicted` (truncation preserves seats —
the delivery-visibility question it answers is "who lost a seat").
